# Phase 3 Tracker — Live Data Integration and Deterministic Outputs

**Purpose:** Track the work required to turn the 44 admitted Phase 2 inputs into lean, reliable, software-readable Phase 3 outputs.

**Scope:** All 44 `ADMIT` variables from the frozen Phase 1 registry. This is the Phase 3 work queue; the Phase 2 source/implementation tracker remains the historical ingestion record.

**Phase 3 exit condition:** Every admitted variable has a validated live integration, a documented source-hygiene result, and a deterministic numeric output or a deterministic numeric encoding of its qualitative assessment. A source failure produces `STALE` or `BLOCKED`; it never produces an invented observation.

**Original six problem-variable milestone:** Closed and evidence-consistent on 2026-08-29. See [PHASE3-ORIGINAL-SIX-CLOSURE.md](PHASE3-ORIGINAL-SIX-CLOSURE.md). This milestone does not mean that all 44 admitted variables have completed Phase 3.

## Work sequence

1. **Source hygiene inspection** — Confirm that the live source is official or otherwise approved, the retrieved content matches the stated source and period, the parser consumes only source-backed information, and no manual data or annotation is silently treated as an observation.
2. **Deterministic representation** — Keep numeric variables numeric; define a documented transformation for qualitative variables so identical evidence and rules produce identical numeric outputs. The preferred term here is **deterministic encoding**.
3. **Live run** — Execute the approved collector/parser against the live source, preserve the raw input and processing evidence, and confirm fallback behavior without synthetic data.
4. **Phase 3 review** — Confirm schema, units, timestamps, availability status, provenance, reproducibility, and readiness for Phase 4.

## Status values

Use one of: `Not started`, `In progress`, `Blocked`, `Ready for review`, `Complete`, `Deferred`.

For the three qualitative variables, the numeric representation must be agreed before a live score is accepted. A human review may supply an explicit assessment, but it must remain visibly separate from source facts and must not be presented as downloaded or machine-extracted data.

## Minimum completion evidence

For each row, the review note should point to or summarize:

- the approved source and exact endpoint/file/series;
- the source-hygiene finding, including any limitation or manual step;
- the output field, unit, sign convention, and timestamp rule;
- the deterministic transformation or qualitative score mapping, if applicable;
- the live-run result and availability status;
- the relevant test, schema, and source/provenance evidence;
- the reviewer, review date, and final Phase 3 decision.

## Phase 3-to-Phase 4 handoff

The handoff dataset should contain only the fields needed by Phase 4: variable ID, observation timestamp, numeric value or encoded score, unit/scale, availability status, source reference, and a concise quality flag. Narrative evidence and review notes remain supporting records, not model inputs.
